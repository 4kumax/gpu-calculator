# gpu-calculator

Интерактивный калькулятор GPU-инфраструктуры для корпоративных задач.

Проект подбирает класс языковой модели и серверную конфигурацию по выбранным задачам, рассчитывает стоимость аренды и покупки, совокупную стоимость владения и порог экономической целесообразности покупки.

## Возможности

- подбор моделей по задачам, контексту и обязательным возможностям;
- каталог моделей от 9B до 2,8T параметров;
- сравнение NVIDIA RTX 4090, L40S, A100, H100, H200, B200, GB200, GB300 и AMD MI300X;
- расчёт количества GPU, экземпляров модели, серверных узлов и резерва N+1;
- сравнение аренды и покупки на горизонте 1–5 лет;
- разложение TCO на оборудование, ввод, поддержку, энергию, размещение, сеть, хранилище и эксплуатацию;
- отдельная страница `/settings` для управления моделями, GPU, ценами, правилами задач и допущениями;
- локальное сохранение настроек, импорт и экспорт JSON.

## Логика подбора

Пригодность модели определяется тремя независимыми измерениями: классом качества, максимальным контекстом и обязательными возможностями. Наличие контекста в 1 млн токенов или мультимодальности само по себе больше не повышает класс качества.

- класс 5 — верхний frontier: Kimi K3, DeepSeek V4 Pro, GLM-5.3 и Qwen3.8 2.4T;
- класс 4 — frontier: MiniMax M3, Kimi K2/K2.5/K2.6, DeepSeek V4 Flash и DeepSeek-R1, Qwen3.8 Flash Next, GLM-5.3 Flash, Mistral Large 3 и Ring 2.6;
- классы 1–3 — базовые, стандартные и продвинутые модели.

Приоритет «Баланс» выбирает минимально достаточный класс, затем минимальную совокупную стоимость. «Максимум качества» сначала выбирает верхний допустимый класс, а при равном классе использует TCO. Число общих или активных параметров не используется как суррогат качества.

Нативный и расширенный контекст хранятся отдельно. Для mixed-precision моделей можно задать фактический размер чекпоинта вместо приближённой формулы `параметры × битность`. Каталожный минимум GPU всегда дополнительно проверяется по памяти для весов. KV-кэш и рабочая память зависят от движка, длины входа и пакетирования, поэтому в эту оценку не входят и должны подтверждаться нагрузочным тестом.

Пиковая параллельность использует плановую ёмкость экземпляра. До появления результатов нагрузочных испытаний для всех моделей задано нейтральное значение 8 одновременных сложных запросов; его можно изменить в `/settings`. Доля нагрузки относится только к рассчитываемому контуру выбранной модели — стоимость других маршрутов в TCO не включается.

Схема каталога имеет версию 2 и отдельный ключ `localStorage`, поэтому сохранённые данные старой схемы не могут незаметно вернуть прежнее ранжирование.


## Развёртывание

Проект совместим с Vercel и развёртывается как стандартное приложение Next.js:

1. импортируйте репозиторий `4kumax/gpu-calculator` в Vercel;
2. оставьте Framework Preset `Next.js`;
3. команда сборки: `npm run build`;
4. переменные окружения для первой версии не требуются.

Настройки `/settings` в первой версии сохраняются в `localStorage` конкретного браузера. Для единого корпоративного каталога потребуется подключить серверную базу и авторизацию.
